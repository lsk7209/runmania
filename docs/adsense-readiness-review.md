## 3. 신청 전 필수 (사람이 판단·작업해야 하는 항목)

### 3-1. 대량 AI 생성 글 — 최대 리스크 🔴

- `STATUS.md`: "신규 300개 글 작성 진행 중", 5시간 간격 자동 예약 발행.
- `[공식]` Google은 AI 사용 자체가 아니라 **추가 가치 없는 대량 생산(scaled content abuse)** 을 문제 삼음. 자동 생성 + 고유 콘텐츠 거의 없음 = 광고 게재 불가 화면.
- `[업계]` 2026년 3월 코어 업데이트에서 편집 감독 없는 대량 생성 사이트가 50~80% 트래픽 손실.
- 현재 구조: `SITE_PERSONA.P4`에 `requiresHumanReview: true`가 있으나, 실제로는 `bulk-schedule.ts`로 일괄 예약 → **사람 검토가 실제로 일어나는지 코드로 강제되지 않음**.

권고:
1. **신청 전 신규 대량 발행 중단.** 승인 후에도 하루 발행량 제한(예: 1~2편).
2. 발행 글을 전수 감사(5분류: 유지/보강/통합/noindex/삭제). 제목만 다르고 답이 같은 글은 통합 + 301.
3. 글마다 **고유 자료 최소 2~3개**: 직접 촬영 사진, 실측 무게·밑창 마모, 착용 거리(km) 기록, 국내 가격 비교표, 실패 경험 등.
4. 품질 게이트(`seoPipeline.ts buildQualityGate`)가 실패한 글은 예약 발행되지 않도록 `cron.ts`에서도 재검증 (TODO.md #6과 동일 이슈).
5. 신청 시점에는 "소수의 깊은 글 > 다수의 얕은 글". 플레이북 기준 글 수 최소치는 없음.

### 3-2. 리뷰 콘텐츠의 신뢰성 🟠

- 리뷰는 `reviewContent.ts`의 정적 텍스트이며 "착화감", "~라고 평가하는 경우가 많습니다" 등 **직접 착용하지 않았다면 오해를 부르는 표현**이 있음.
- 권고: 직접 착용 여부를 구분 표기 ("직접 착용" / "공식 사양·러너 후기 종합"). 직접 안 신어봤다면 후자로 명시(이번 About에 "종합·정리" 문구를 추가함 — 실제 제작 방식과 일치하는지 확인 필요).
- 리뷰 JSON-LD의 `author`는 Organization. 가능하면 실명 에디터 프로필(`/about` 내 소개)을 추가.

### 3-3. 건강(YMYL 인접) 콘텐츠 🟠

- "무릎 통증 러닝화", "족저근막염 신발" 류 글은 의료 인접 주제.
- 현재 면책은 있으나 **감수자·전문가 표기가 없음**. 가능하면 물리치료사·스포츠의학 전문가 감수 또는 최소한 공식 출처(대한정형외과학회 등) 인용.
- "~에 효과적", "교정" 같은 표현은 `persona.avoid` 규칙대로 완화.

### 3-4. 운영자 정보 🟡

- About/Contact에 **운영자·에디터의 실체**(이름 또는 경력, 러닝 경험)가 없음. `[공식]` 정확한 바이라인·제작 과정 공개 권장.
- 블로그 JSON-LD의 author가 "런닝화매니아 에디터"(Person 타입)인 점은 어색 — 실명이 있으면 교체, 없으면 Organization으로 변경.

## 6. 권장 실행 순서

1. **(즉시)** 이번 수정 사항 배포 → Vercel 프리뷰에서 푸터·Contact·Terms 확인
2. **(1주)** 신규 대량 발행 중지, 발행 글 전수 감사표 작성 (URL / 고유 자료 / 중복 / 처리)
3. **(1~2주)** 핵심 가이드 3개 + 리뷰 5~10개를 직접 사진·실측·착용 기록으로 보강
4. **(1~2주)** 운영자/에디터 프로필, 건강 글 출처·감수 표기 추가
5. **(1주)** Search Console에서 렌더링 HTML·색인 상태 확인, 색인 안 된 얇은 글 `noindex` 또는 통합
6. **(신청)** 점수 85점 이상 + 재크롤링 요청 후 신청
7. **(승인 후)** 광고는 한 변수씩 실험, 모바일 광고 밀도 30% 이하, 슬롯 `min-height` 확보, 홈·문의·약관 페이지는 광고 제외 검토

## 8. 2차 조치 (추가 수정 완료, 2026-10-22)

| # | 문제 | 조치 |
|---|------|------|
| 1 | `scripts/prerender.ts`가 초기 HTML에 **영어 보일러플레이트**(심지어 "AdSense review"를 언급하는 문장)를 삽입. 사용자는 React 한국어 화면을 보므로 크롤러/사용자 내용 불일치 = 클로킹 위험 | 제목·요약·사이트 링크만 담은 최소 한국어 셸로 교체 |

| 5 | 글 상세에 제작 방식/면책 없음 | 모든 글 하단에 에디터 검토·AI 활용·의료 면책 고지 |

### 운영 시 알아둘 점
- 관리자 `bulk_create` + 자동 예약 경로(`admin-blog.ts`)는 기존 동작 유지(테스트가 이를 검증). 대신 cron의 일일 상한이 발행 속도를 제한합니다.
- 프리렌더는 홈·도구 등 비-글 페이지의 정적 HTML에서 AdSense 스크립트를 제거합니다(기존 설계). 소유 확인은 `google-adsense-account` 메타로 유지됩니다.
