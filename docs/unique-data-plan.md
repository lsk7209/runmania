## 0. 원칙 (반드시 지킬 것)

1. **실제로 한 것만 기록한다.** 측정하지 않은 값, 신어 보지 않은 신발의 착화감은 쓰지 않는다.
2. 자료가 없는 리뷰는 지금처럼 "공식 사양·후기 종합" 표기를 유지한다. 자료가 생긴 리뷰만 "직접 측정" 섹션을 붙인다.
3. 숫자에는 측정 조건을 같이 적는다 (저울 종류, 사이즈, 날짜).
4. 사진은 직접 촬영한 원본만 쓴다. 제조사 이미지·AI 생성 이미지를 "실물"처럼 쓰지 않는다.

## 3. 사이트 반영 방법 (자료가 생긴 뒤 개발)

1. 리뷰 데이터(`src/data/reviewContent.ts`)에 선택 필드 `testRecord`를 추가한다: 실측값, 총 착용 km, 기간, 사진 경로.
2. 리뷰 페이지는 `testRecord`가 **있을 때만** "직접 측정 기록" 섹션을 보여준다. 없으면 지금의 "공식 사양·후기 종합" 고지를 유지한다.
3. 직접 측정 리뷰에는 측정일과 측정자(운영자 프로필)를 같이 표시한다.
4. 가이드 글은 DB 본문에 사진·표를 넣는다 (DB 접근 필요).

## 4. 현재 이미지 문제 (자료 확보 전 처리 필요)

- `src/assets/shoes/*.png` 10장은 **AI 생성 이미지**로 보인다.
  - 근거: 미드솔 글자가 깨져 있고("Pppoe ll ORRO"), 호카 이미지에 "MOKA" 표기와 다른 브랜드식 줄무늬가 있다.
- 이 이미지들이 특정 모델 리뷰의 대표 이미지로 쓰여 **실제 제품 사진으로 오인될 수 있고**, 실존 브랜드 로고를 흉내 낸다.
- 처리 순서:
  1. 즉시: 이미지에 "실제 제품 사진이 아닌 참고용 일러스트" 표기 (코드로 처리)
  2. 직접 촬영 사진이 생기면 모델별로 교체
- Unsplash 사진(블로그 대표 이미지 일부)은 Unsplash 라이선스상 상업적 사용 가능 — 유지.
